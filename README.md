# 自然人憑證註冊與登入畫面原型

2026-10-23，設計草稿。範圍僅限 IC 卡／行動憑證註冊、登入、聯絡驗證、既有會員綁定、完成與必要救援，不包含招租申請及中心端業務管理。

## 開啟方式

直接以 Edge 或 Chrome 開啟 `index.html`，不需安裝套件或啟動伺服器。整包移機請保留資料夾結構。

- 「操作原型」：依畫面按鈕前進，左側依流程列出畫面。
- 「畫面關聯圖」：三張含編號、畫面縮圖及操作箭頭的關聯圖，點節點可開啟畫面；下方完整關聯表包含返回與例外。
- 「順序畫冊」：依同一順序列出所有畫面；可使用瀏覽器列印另存 PDF。
- 「來源與待決策」：官方資料取得方式、版本限制、正式規則待確認事項。

首次開啟停在 U04-01 憑證方式選擇。從 U01-02 可開始完整註冊路徑，從 U01-01 可開始登入路徑。

## 如何檢視不同流程

畫面上方有規劃者專用控制，與民眾實際畫面分開：

1. 會員對應：新會員、既有會員待綁定、已綁定、會員不可登入。
2. 密碼候選政策：A 全員設定、B 憑證會員免強制設定。
3. 聯絡驗證候選：手機及 Email 皆驗證、或擇一驗證。
4. 在認證等待頁選成功、失敗、逾時或取消，再看後續畫面。
5. 在本站密碼救援入口可選原會員是否已有本站密碼；未設者不得直接走重設流程。

原型驗證碼為 `123456`，可先輸入其他值檢查錯誤提示。填寫資料只留在本頁記憶體，刷新即重設；不寄信、不發簡訊、不儲存正式資料。所有認證與建帳成功皆為示範狀態。

## 主要路徑

- IC 卡新註冊：U01-02 → U04-01 → U05-01 → EXT-C-01（外部介面參考）→ U05-02 → U05-02-success → U07-01 → U07-02／03 → 依政策 U07-06 或略過 → U09-01 → U01-01。
- 行動憑證新註冊：U01-02 → U04-01 → U06-01 → U06-02（推播）或 U06-02-qr（掃碼）→ U06-02-success → U07-01 → 共用建帳流程。
- 已綁定登入：U01-01 → 憑證認證 → 成功 → U01-03。會員狀態不允許時至 U01-04。
- 既有會員綁定：認證成功 → U08-01 → 帳密或候選聯絡驗證 → U08-02 → U08-04 → U01-01。
- 帳號救援：U10-01 → U10-02 → U10-03 → U10-04 → U10-05 → U01-01。未設密碼則至 U10-01-unset。

## 檔案

- `index.html`、`style.css`、`tokens.css`、`app.js`：可編輯本機原型來源。
- `screens/`：38 個編號畫面／狀態的 PNG，可放入 Axure、文件或簡報。
- `screen-manifest.json`、`畫面與來源清單.md`：編號、名稱、用途與來源。
- `relations.json`：完整操作關聯資料。
- `relations-1.svg`～`relations-3.svg`：含縮圖的關聯圖；須與 screens 及 index.html 保持相對位置。可修改 SVG 與 JSON／原型程式。
- `assets/official/`：官方頁面實際截圖與 App Store 公開原圖，未重繪外部介面。
- `evidence/`：來源 HTML、版本查詢、瀏覽器檢查截圖及取證紀錄。
- `references/ui-guidelines/`：本次引用的使用者 UI 規範快照，非另行核定版本。
- `validation.json`：本機原型的實際檢查結果。

## 規則與驗證邊界

本站畫面參照使用者的 UI 規範：深藍主操作、米白背景、淡灰藍分區、綠色成功狀態、16px 內文、44px 控制項、8px／16px 圓角與可見焦點。識別圖示「住」為原型文字標記，非新製官方標誌。

密碼政策、聯絡驗證政策、實際回傳欄位與可修改規則、綁定驗證方式、PIN UI 歸屬、行動介接模式、重試／效期／停用、正式告知及客服內容、完成後是否自動登入，均未擅自核定。

已檢查按鈕目標、核心流程、驗證碼錯誤與資料保留、密碼候選、既有會員綁定、停用分支、救援及 375px 全畫面水平溢出。這些是本機原型檢查；沒有驗證正式憑證、驗章、資料庫、Session、權限、簡訊或郵件。尚未完成完整讀屏與正式無障礙符合性驗證。
